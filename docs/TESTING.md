## 2. Why the existing test fails

```tsx
// __tests__/home-screen-test.tsx
import HomeScreen from "@/app/(tabs)";

test('Text renders correctly on HomeScreen', async () => {
  const { getByText } = await render(<HomeScreen />);
  getByText('Welcome!');
});
```

1. **Import-time throw.** `HomeScreen` imports `context/AppContext.tsx` → `api/*` → `api/supabaseClient.ts`, which throws when `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` isn't set.
2. **No providers.** `HomeScreen` calls `useApp`, `useData`, `useCricketMatches` and `useFootballMatches`, which need their providers (and a `QueryClientProvider`).
3. **Wrong text.** The screen never renders "Welcome!"; it renders `Hello, {userName}!`, and only once a role is loaded. With no role it shows "Loading..." and redirects to `/login`.
4. **Possibly transform config.** `transformIgnorePatterns` doesn't list `@nkzw/create-context-hook` or `lucide-react-native`. Whether that matters wasn't checked, because the suite fails earlier.

## 4. Making tests runnable

These are the minimal steps. They are test-only changes; none changes app behaviour.

### 4.1 Mock the Supabase client

```ts
// __mocks__/supabaseClient.ts  (or jest.mock in a setup file)
jest.mock('@/api/supabaseClient', () => ({
  supabase: {
    auth: {
      signInWithPassword: jest.fn(),
      signUp: jest.fn(),
      signOut: jest.fn(),
      getUser: jest.fn(),
    },
    from: jest.fn(() => ({
      select: jest.fn().mockReturnThis(),
      insert: jest.fn().mockReturnThis(),
      delete: jest.fn().mockReturnThis(),
      eq: jest.fn().mockReturnThis(),
      order: jest.fn().mockResolvedValue({ data: [], error: null }),
      single: jest.fn().mockResolvedValue({ data: null, error: null }),
    })),
  },
}));
```

Or set a dummy `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in a Jest setup file and mock network calls. Mocking the module is simpler and keeps tests offline.

### 4.2 Mock AsyncStorage

```ts
jest.mock('@react-native-async-storage/async-storage', () =>
  require('@react-native-async-storage/async-storage/jest/async-storage-mock')
);
```

### 4.3 Render with providers

```tsx
function renderWithProviders(ui: React.ReactElement) {
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } });
  return render(
    <QueryClientProvider client={client}>
      <AppProvider>
        <DataProvider>
          <CricketMatchProvider>
            <FootballMatchProvider>
              <ActionSheetProvider>{ui}</ActionSheetProvider>
            </FootballMatchProvider>
          </CricketMatchProvider>
        </DataProvider>
      </AppProvider>
    </QueryClientProvider>
  );
}
```

`expo-router` hooks also need mocking (`useRouter`) or the `expo-router/testing-library` helpers.

### 4.4 Fix the Home test's expectation

Seed AsyncStorage with `user_role = 'player'` and `user_name = 'jane'`, then assert `Hello, jane!`.

## 5. What to test first

Ordered by risk. Engine tests come first because [BUSINESS_LOGIC.md §6](BUSINESS_LOGIC.md#6-known-defects) lists 20 known defects, and fixing them without tests risks breaking what works.

| Priority | Area | Type | Examples |
|----------|------|------|----------|
| 1 | `scoreEngine.handleScore` | Unit | runs add to team, batsman, bowler; 6 legal balls complete an over; odd runs swap strike; wide adds 1 + runs and isn't a legal ball; chase passes target → innings end called |
| 2 | `wicketEngine` | Unit | bowled credits bowler; run out doesn't; all out at XI − 1; last-ball wicket ends innings (currently fails, C6) |
| 3 | `inningsEngine.handleInningsEnd` | Unit | runs margin; wickets margin (currently wrong, C8); tie (currently wrong, C9) |
| 4 | `api/playerApi.mapPlayerRecord` | Unit | nulls → 0; bestBowling text; ratings default |
| 5 | `api/*` functions | Unit with mocked client | each hits the right table; `deletePlayerInfo` targets `players` (currently fails) |
| 6 | Create Match `canProceed` rules | Component | each step's enable/disable conditions ([BUSINESS_LOGIC.md §3.1](BUSINESS_LOGIC.md#31-steps-and-validation)) |
| 7 | Login flow | Component | missing fields alert; role null alert; success stores role and navigates |
| 8 | `useApp` | Hook | role persistence, logout clears role |

### 5.1 Testing the engines

The engines call `showActionSheetWithOptions`, `Alert.alert` and `setTimeout`. To test them today:

- pass `jest.fn()` for `showActionSheetWithOptions` and invoke its callback with an index,
- `jest.spyOn(Alert, 'alert')` and call the button's `onPress`,
- use `jest.useFakeTimers()` and `jest.advanceTimersByTime(300)`,
- mock `expo-haptics`.

Example:

```ts
import { handleScore } from '@/sports/cricket/engines/scoreEngine';

jest.mock('expo-haptics', () => ({ impactAsync: jest.fn(), ImpactFeedbackStyle: { Medium: 'medium' } }));

test('a single swaps strike and adds to batsman and bowler', () => {
  const match = makeMatch({ striker: 'p1', nonStriker: 'p2', bowler: 'b1' }); // test helper
  const updateLiveMatch = jest.fn();

  handleScore(1, undefined, {
    currentMatch: match,
    updateLiveMatch,
    setLiveMatch: jest.fn(),
    getTeamById: () => ({ name: 'A' }),
    getPlayerById: (id) => ({ id, name: id }),
    handleInningsEnd: jest.fn(),
    selectNewBowler: jest.fn(),
    setLastBalls: jest.fn(),
  });

  const innings = updateLiveMatch.mock.calls.at(-1)[0].innings[0];
  expect(innings.runs).toBe(1);
  expect(innings.balls).toBe(1);
  expect(innings.currentStriker).toBe('p2');
  expect(innings.batsmen.find(b => b.playerId === 'p1').runs).toBe(1);
  expect(innings.bowlers.find(b => b.playerId === 'b1').runs).toBe(1);
});
```

(`makeMatch` doesn't exist yet; it would build a `CricketMatch` with one empty innings.)

Because the engines mutate their input (C4), build a fresh match for each test.

## 6. Manual regression checklist

Run before and after any change to these areas. Source: [PROJECT_AUDIT.md §14](PROJECT_AUDIT.md#14-existing-functionality-that-must-not-break). Test on a phone or simulator as well as web, because `Alert` button flows only work on native.

- [ ] Sign up, sign in, role loads, Home shows the right badge.
- [ ] Restart the app: still signed in; Supabase writes still work (checks session persistence).
- [ ] Log out returns to Login.
- [ ] Sport switcher persists after restart; Badminton / Carrom / UNO show "Coming Soon".
- [ ] Teams: list loads from Supabase; add team; add player (with and without team); pull to refresh.
- [ ] Stadiums: list, add.
- [ ] Cricket create: all four steps, substitutes with each permission, Save as Upcoming, Start Now.
- [ ] Live scoring: each run button, each extra with and without extra runs, each dismissal, swap strike, change bowler, end of over, innings break with new openers, automatic result, manual end.
- [ ] Match details: scorecard and info tabs for live and completed matches.
- [ ] Player and team detail screens open from lists.
- [ ] Admin-only buttons are hidden for a player account.
